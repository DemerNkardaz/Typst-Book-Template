# 2026-11-01

Проект хорошо организован как расширяемый Typst-шаблон: контент, настройки, стили и сборочные модули разделены. Для черновиков и базового экспорта в PDF он выглядит практичным; для печатного тиража конвейер пока требует дополнительной проверки.

* Наиболее существенный риск — конвертация изображений в `build/modules/image_process.py`: обработчик предполагает RGB для входных данных, повторно сохраняет изображения в JPEG с потерями, а ошибки декодирования пропускает без сообщения. Это может привести к отличиям цвета или к тому, что отдельные изображения останутся неконвертированными.
* Настройка `pdf-validator` в `settings/build.yml` не запускает отдельный валидатор: значение передаётся Typst как стандарт PDF, после чего файл ещё изменяется скриптом. Поэтому фактическое соответствие PDF/A или PDF/UA не подтверждается. Также README заявляет поддержку Python 3.8+, хотя аннотации `dict[str, ...]` требуют Python 3.9+.

* Есть незавершённые или неиспользуемые части интерфейса: `--as png` и `png-ppi` не влияют на результат, а общий `style.use` не применяет целевой стиль `page`. Кроме того, запуск Makefile без `m` передаёт пустой `--mode`, что может рассинхронизировать выбранный режим сборки и режим макета Typst.

Перед использованием для печати стоит добавить реальные проверки PDF после постобработки и тесты на изображения RGB, CMYK и grayscale. Для повседневной авторской работы проект уже задаёт понятную основу; для издательского production-процесса нужны эти проверки и более предсказуемая обработка ошибок.
Это статическая оценка кода; сборку и соответствие PDF-стандартам отдельно не проверял.
